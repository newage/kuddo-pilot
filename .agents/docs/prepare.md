# ТЗ (верхньорівневе): Kuddo Pilot

> Greenfield-проєкт. Документ фіксує цілі, межі, архітектуру та ролі без деталізації. Рішення — у `decisions-chat-ui.md`, задачі — у `tasks-chat-ui.md`.

## 1. Мета

Власний чат-UI для дитини з AI-вчителями (предметами) на базі Gemini, з рольовим доступом (RBAC). Дитина входить через Google, вибирає вчителя, веде кілька чатів зі збереженою історією. Доступ до вчителів визначається роллю. Історія чату зберігається в БД у стиснутому вигляді (rolling-підсумок).

## 2. Межі

**В межах:**
- власний чат-UI на Next.js (стрімінг, список чатів, вибір вчителя);
- вхід через Google OAuth 2.0;
- RBAC: ролі `admin` і `user`, доступи ролей до вчителів (зберігаються в БД);
- профіль дитини (ім'я, вік, хобі, самоопис);
- зберігання чатів у БД з автоматичним підсумовуванням, soft delete чату;
- Next.js-застосунок: UI, API-роути, мінімальний admin-портал (користувачі, ролі, вчителі та їхні промпти, доступи);
- локальна розробка лише через Docker (файли в `docker/`), продакшн-деплой на Vercel.

**Поза межами:**
- Open WebUI та OpenAI-сумісний шлюз;
- роль `parent`, статистика, зв'язок parent↔діти (відкладено);
- інтеграція з Google Drive/Docs;
- мобільні застосунки;
- біллінг і квоти;
- fine-tuning моделей;
- фільтрація вмісту самоопису, GDPR і ретеншн.

## 3. Технологічний стек

| Шар | Технологія |

| Чат-UI | Next.js (App Router), Vercel AI SDK (`useChat`), shadcn/ui |

## 4. Архітектура (верхній рівень)

```
Дитина ─► Next.js UI (useChat) ─► POST /api/chat ─► сесія + права на вчителя
                                        │                  │
                                        │                  ▼
                                        │             PostgreSQL (чат: ≤10 записів)
                                        ▼
                                   Gemini (стрімінг) ─► відповідь у UI
                                        │
                                        └─ після відповіді (фон): 10 записів → згортання в підсумок
```

- **Next.js** — один застосунок: UI, API-роути, Auth.js, виклики Gemini, підсумовування чатів, admin-портал.
- **Один маршрут `/api/chat`:** Auth.js-сесія, перевірка доступу ролі до вчителя, контекст = системний промпт вчителя + профіль дитини + підсумок + поточні записи.
- **PostgreSQL** — єдине сховище: користувачі, ролі, вчителі, доступи, профілі, чати.
- Окремого бекенду і довгоживучих процесів немає.

## 5. RBAC

**Ролі:**

| Роль | Доступ |
|---|---|
| `admin` | повне керування: користувачі, ролі, вчителі та їхні промпти, доступи |
| `user` | чат + усі дозволені його ролі вчителі |

**Принципи:**
- права призначаються через **ролі**, не індивідуально;
- ресурс під контролем доступу — **вчитель** (`teacher`); перевірка виконується в `/api/chat` для кожного запиту;
- нові користувачі після першого входу не мають доступу, доки адмін не призначить роль;
- принцип мінімальних привілеїв;
- джерело істини для ролей і доступів до вчителів — БД.

## 6. Дані (БД)

Предметні області:

1. **RBAC і вчителі:** користувачі, ролі, `teacher` (назва, предмет, системний промпт, активність), зв'язок «роль → дозволені вчителі».
2. **Профіль:** ім'я, вік, хобі, самоопис дитини; редагується нею в будь-який час.
3. **Чати:** `chat` — окрема сутність (id, користувач, вчитель, назва, ознака прихованого) і записи чату. Багато чатів на пару «користувач + вчитель»; вчитель задається при створенні, зміна вчителя = новий чат.

Системний промпт вчителя і профіль підставляються в контекст кожного запиту та не потрапляють у записи чату й підсумок. Редагування промпту вчителя діє і на наявні чати (версіонування немає).

Видалення чату — soft delete: чат ховається зі списку, записи в БД лишаються.

### Правило підсумовування чату

Для кожного **чату** у БД зберігається **не більше 10 останніх записів**. Записом є або звичайне повідомлення, або підсумок.

1. Поки записів менше 10 — нові повідомлення додаються як є.
2. Коли набирається 10 записів, вони згортаються в **одне підсумкове повідомлення** (AI формує підсумок; попередній підсумок, якщо він є, входить у новий). Промпт підсумовування один для всіх вчителів.
3. Підсумок + нові повідомлення (до 9) знову дають 10 записів → знову згортання в один підсумок.
4. Цикл повторюється; оригінальні повідомлення, що ввійшли в підсумок, з БД видаляються.

Інваріант: після першого згортання **перший із записів чату завжди підсумок** усіх попередніх повідомлень (кумулятивний). У UI підсумок показується першим повідомленням чату.

Згортання виконується у фоні після відповіді (відповідь без затримки), у транзакції з блокуванням чату. Збій згортання: записи лишаються, наступне повідомлення пробує знову (чат тимчасово довший за 10).

Підсумок і поточні повідомлення передаються моделі як контекст розмови.

## 7. Функціональні вимоги (high-level)

1. Вхід через Google; автоматичне створення користувача без ролі й без доступу.
2. Адмін призначає роль користувачу (`admin` / `user`).
3. Чат із вчителем (Gemini) у власному UI з урахуванням прав ролі на вчителя; «Новий чат» з вибором вчителя; видалення (приховування) чату.
4. Збереження історії чату в БД за правилом підсумовування (розд. 6).
5. Профіль дитини: перегляд і редагування.
6. Admin-портал: користувачі, ролі, вчителі та їхні промпти, доступи ролей до вчителів.

## 8. Нефункціональні вимоги (high-level)

- **Безпека:** секрети лише в env/secret storage; перевірка прав на кожен запит до `/api/chat`.
- **Відтворюваність:** локальне середовище працює лише через Docker і піднімається однією командою (`docker compose -f docker/compose.yml up`); запуск без Docker не підтримується.
- **Консистентність:** підсумовування чату атомарне (підсумок записується й старі повідомлення видаляються в одній транзакції, чат заблоковано).
- **Експлуатація:** міграції БД версіонуються; CI/CD на Vercel для Next.js.
- **Локалізація:** інтерфейс і документація — українська.

## 9. Етапи (орієнтовно)

1. **Фундамент:** репозиторій, Docker (`docker/`: Next.js + Postgres), env-конфігурація.
2. **Схема БД і авторизація:** Google OAuth, ролі `admin` / `user`.
3. **Підсумовування і `/api/chat`:** правило §6, доступ до вчителів, стрімінг Gemini.
4. **Чат-UI і профіль:** список чатів, вибір вчителя, профіль дитини.
5. **Admin-портал:** користувачі, ролі, вчителі, доступи.
6. **Production:** деплой, hardening.
