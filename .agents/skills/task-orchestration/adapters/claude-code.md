# Адаптер: Claude Code

Доповнює [`SKILL.md`](../SKILL.md): як виконати протокол саме в Claude Code. Звірено з документацією й поведінкою Claude Code станом на 2026-09; якщо поведінка розходиться — вір інструменту й онови цей файл.

## Можливості

| Можливість | Як |
|---|---|
| запуск | інструмент `Agent`: `subagent_type`, `description`, `prompt` (бриф), `model` |
| модель | `model` у виклику — лише аліас: `haiku`, `sonnet`, `opus`, `fable`. Повний ID приймає тільки поле `model` у визначенні кастомного агента. Без параметра — модель із визначення агента, далі `CLAUDE_CODE_SUBAGENT_MODEL`, далі модель сесії. Відхилене значення — виправ аліас, а не запускай без `model` |
| паралель | кілька викликів `Agent` в одному повідомленні |
| фон | за замовчуванням; результат приходить сповіщенням. Хвиля завершена, коли прийшли всі сповіщення |
| продовження | `SendMessage` тому самому агенту: він зберіг контекст і власну помилку. Інструмент буває відкладеним — спершу `ToolSearch` із `select:SendMessage` |
| лише читання | `Explore` з `model: "haiku"` — тільки пошук і збір фактів: він читає уривки й не рецензує. Рев'ю, перевірка, гіпотези, концепти — `general-purpose` з «лише читання» в брифі |
| зупинка | `TaskStop` з ID агента |
| статус щохвилини | `Monitor` — див. нижче |

Не використовуй `subagent_type: "fork"`: для нього `model` ігнорується й успадковується модель сесії.

`Explore` з v2.1.198 успадковує модель сесії (зі стелею Opus), тож без явного `model: "haiku"` дешевого пошуку не буде.

## Таблиця рівнів

- Моделі — аліаси параметра `model` інструмента `Agent`.
- Ціни — `https://platform.claude.com/docs/en/about-claude/pricing.md`; моделі й вікна контексту — `https://platform.claude.com/docs/en/about-claude/models/overview.md`.
- Типова розкладка лінійки Claude: 1 — Haiku, 2 — Sonnet, 3 — Opus. Fable — понад рівень 3, субагентам не призначається.
- Haiku не підтримує effort, і вікно контексту в нього менше, ніж у старших моделей.

## Статус щохвилини

Субагенти працюють у фоні, і між сповіщеннями оркестратор неактивний. Будильник — `Monitor` (буває відкладеним: спершу `ToolSearch` із `select:Monitor`): кожен рядок stdout скрипта — подія, що будить оркестратора. Подія — не привід чекати: після рядка статусу оркестратор повертається до підготовки перевірки.

`Monitor` може вимагати дозволу. Поки запит висить, монітор не стартує, і статусів немає: у реальному прогоні він запустився на ~30 хв пізніше за агентів, коли ті вже закінчили. Тому порядок такий:

1. Створити нову теку хвилі `/tmp/<задача>/w<N>` — своя на кожну хвилю, інакше старі маркери одразу дадуть «готово». Запустити `Monitor` з `timeout_ms: 1800000` і дочекатися відповіді «Monitor started»: запит дозволу, якщо буде, з'явиться до старту агентів.
2. Запустити агентів хвилі одним повідомленням; у брифі довгого агента шлях чекпойнтів — `<тека>/<ім'я>.progress`.
3. Одним записом покласти в `<тека>/agents` рядки `<ім'я>:<output_file>` (ім'я — без двокрапки); шлях `output_file` друкується в результаті запуску `Agent`.
4. На кожне сповіщення про завершення — `touch <тека>/<ім'я>.done`, потім перевірка результату.
5. Коли готові всі, скрипт завершується сам. Монітор більше не потрібен раніше — `TaskStop`. Закінчився за тайм-аутом, а хвиля ще йде, — запустити той самий скрипт знову: час старту він бере з теки.

Щоб запит дозволу не з'являвся щоразу, `Monitor` варто додати в дозволені інструменти налаштувань Claude Code.

```bash
DIR=/tmp/<задача>/w<N>
[ -f "$DIR/start" ] || date +%s > "$DIR/start"; start=$(cat "$DIR/start"); touch "$DIR/agents"
while true; do
  sleep 60
  now=$(date +%s); total=0; ready=0; line=""
  while IFS=: read -r name f; do
    [ -n "$name" ] || continue
    total=$((total + 1))
    if [ -e "$DIR/$name.done" ]; then ready=$((ready + 1)); continue; fi
    if ! m=$(stat -L -c %Y "$f" 2>/dev/null); then line="$line; $name журнал недоступний"; continue; fi
    cp=$(tail -n 1 "$DIR/$name.progress" 2>/dev/null)
    line="$line; $name idle=$(( now - m ))с${cp:+ «$cp»}"
  done < "$DIR/agents"
  echo "$(date +%H:%M) +$(( (now - start) / 60 ))хв готово $ready/$total$line"
  [ "$total" -gt 0 ] && [ "$ready" -eq "$total" ] && exit 0
done
```

- Журнал — повний транскрипт агента. Лише `stat`: читання вмісту переповнить контекст оркестратора. На macOS замість `stat -L -c %Y` — `stat -L -f %m`.
- «журнал недоступний» у події — перевір шлях у `<тека>/agents`: скрипт працює далі, але цього агента не бачить.
- Одна подія — один зведений рядок про всю хвилю; скільки лишилось, оркестратор додає з оцінки плану.

`Monitor` недоступний — Bash із `run_in_background: true` і `sleep 60`: одне пробудження на запуск, перезапускай щохвилини.

## Читання пакетами

- Кілька викликів `Read`, `Grep`, `Glob` в одному повідомленні виконуються паралельно — саме так читають набір файлів.
- Спершу `Grep` чи `Glob`, потім `Read` лише знайдених місць; для великого файлу — `Read` з `offset` і `limit`.
- Широкий пошук по дереву — окремий `Explore` з `model: "haiku"`: він повертає висновок, а не вміст усіх файлів у контекст оркестратора.
- Шелл замість `Read` виграшу не дає: паралельні виклики коштують того самого ходу, а `cat` не дає ні номерів рядків, ні захисту від величезного файлу. Оболонка — лише для того, чого інструменти не вміють: `stat`, `wc -l`, `grep -c`.

## Обмеження середовища

- Субагент не бачить розмови й не може спитати користувача: `AskUserQuestion` йому недоступний. Звідси стоп-умови в брифі.
- Запити дозволів фонових агентів спливають в основній сесії, а агент тим часом мовчки чекає. Оркестратор цих запитів не бачить і вирішити не може — лише користувач. Тому при підозрі на зависання статус прямо просить перевірити, чи не висить запит дозволу.
- Чекпойнти в тимчасовий файл просити лише тоді, коли запис туди не потребує дозволу: перевір правила дозволів або зроби пробний запис сам до хвилі. Потребує — покладайся на журнал.
- Субагенти можуть запускати власних субагентів до трьох рівнів углиб; жорстко вкладеність вимикає `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`.
- Технічна межа — 20 одночасних субагентів (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), поріг затвердження плану в скілі нижчий.
- Фонові субагенти мають урізаний набір інструментів.
- `isolation: "worktree"` гілкується від основної гілки, а не від поточного HEAD: субагент не бачить незакомічених змін і поточної гілки, а результат потребує злиття.

## Effort і сталі ролі

Параметра effort у виклику `Agent` немає — лише у визначенні кастомного агента `.claude/agents/<name>.md` (поля `model`, `effort`, `tools`). Якщо в проєкті є кастомні агенти під рівні чи ролі — використовуй їх; модель із виклику перекриває модель із визначення.

## Workflow

Інструмент `Workflow` цей скіл не викликає: для нього потрібен явний запит користувача. Якщо користувач сам попросив workflow — див. скіл `workflow-authoring`.
