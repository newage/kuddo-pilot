# Режим: архітектура

Доповнює [`SKILL.md`](../SKILL.md). Рішення приймає людина; субагенти готують для нього матеріал, але не обирають.

## Зв'язок з `design-funnel`

Якщо в проєкті є `design-funnel`, цей режим працює всередині нього і не пропускає його гейтів:

| Гейт воронки | Що це означає для хвиль |
|---|---|
| проблема й «Дано» підтверджені користувачем | хвиля 1 наповнює «Дано»; хвиля 2 — лише після підтвердження |
| концепт розробника питається першим | його концепт — один з концептів хвилі 2, а не альтернатива, яку показують після |
| коротка глибина воронки | хвилі 2–3 не запускаються: концепт очевидний, досить мапи |

Діалог «одне питання за раз» лишається за оркестратором і не делегується. Без `design-funnel` ті самі гейти — прямим питанням користувачу.

## Хвилі

1. **Мапа поточної системи.** Один агент на модуль чи межу: точки входу, потоки даних, контракти, хто споживає. Окремо — обмеження (обсяги, вимоги до швидкодії, наявні контракти) і «де в коді вже розв'язували схоже». Факти з координатами; мапа модуля зазвичай виходить довгим субагентом (крок 4).
2. **Концепти.** 2–3 агенти, кожен розробляє один концепт на тому самому наскрізному прикладі. Осі різні за суттю — мінімальна зміна, чиста архітектура, прагматичний компроміс — або ті, що диктує задача. Зазвичай довгі субагенти: цілісність концепту важливіша за швидкість, тож під контроль прогресу.
3. **Критик.** На кожен концепт — свіжий агент, який намагається його зламати: сценарії відмови, ризики міграції, приховані зв'язки.
4. **Синтез — оркестратор.** Порівняльна таблиця, рекомендація одним рядком, відкриті питання — користувачу.

Концепти без критика — три презентації без стрес-тесту. Критик без мапи критикує уявну систему.

Бриф агентів-концептів — однаковий дослівно: той самий блок «Дано», ті самі обмеження, той самий приклад. Відрізняється лише назва осі. Інакше таблиця порівняння зводить несумірне: один агент вважав, що схему даних чіпати можна, інший — що ні.

## DoD агента-концепту

- той самий наскрізний приклад з конкретними значеннями, що й у решти;
- як концепт працює на ньому;
- ціна: що побудувати чи змінити, які модулі зачіпає — з координатами;
- що концепт робить неможливим — найважливіше і найчастіше пропущене;
- шлях міграції з поточного стану;
- без коду й без деталей нижче рівня концепту.

## Межі

- Ні агенти, ні оркестратор у синтезі не усереднюють концепти в химеру на кшталт «A, але з міграцією з C». Гібрид — це окремий концепт, і він проходить критика, як решта.
- Агенти не обирають.
- Деталі — лише після вибору концепту: відповідь, узгоджена до вибору, викидається разом з відкинутим концептом.
- Лише читання.
